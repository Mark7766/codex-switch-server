Codex Switch · 工具 · ai-working-ok

ai-working-ok

AI 工作护栏 —— 把工作当成代码来管理。给任何一个「工作项目」装上三层记忆 + PDCA， 让 AI 每次开工记得上下文、每次收尾记下成果，不会"做了任务 X 却丢了上下文 Y"。 主要运行在 Codex Desktop，不用会编程。

这是什么

ai-working-ok 是一套装进你工作文件夹的「记忆 + 流程」护栏。它把 做研究、写报告、做运营、写方案这类知识工作，当成代码项目来管理： AI 每做一个任务，都先读取项目记忆再开工，做完后把成果和决策写回记忆。

  • 三层记忆：长期（项目是什么）· 中期（做了什么决策）· 短期（最近干了啥）
  • PDCA 闭环：Plan → Do → Check → Act，每个任务有始有终
  • 主要平台：Codex Desktop（也支持 Claude Cowork / Claude Code / Copilot）
  • 零依赖：纯 Markdown + 脚本，全中文，免费开源

适合谁

适合 不写代码、但用 AI 干活的"知识工作者"：新媒体运营、市场、商业分析、 教育、财务、研究、创意等，只要你的活儿是按「项目」组织的。

💡 常见顾虑："我需要会编程吗？" —— 不需要。ai-working-ok 处理的是文档、 表格、方案、报告，不是代码；所有"装护栏"的动作由 AI 自动完成。

解决什么问题

  • 上下文丢失：每次新开对话 AI 都忘了背景，你要重新解释一遍 → 记忆跟着项目走。
  • 决策不一致：这次用方法 A、下次用方法 B，前后没延续 → 用「工作决策记录（WDR）」固定下来。
  • 质量忽高忽低：没有统一的检查标准 → 每个任务走一遍 PDCA。
  • 经验留不下来：做完一个项目，收获留在对话里 → 任务历史沉淀成你的资产，下个项目直接用。

快速开始 · 安装（约 30 秒）

前提

电脑上装有 Codex Desktop（或 Claude Cowork）。

在 Codex Desktop 里对你的 AI 说一句话

安装 https://github.com/Mark7766/ai-working-ok/releases/latest

也可以直接说：install ai-working-ok。AI 会自动下载并开始定制。

想自己手动解压？

curl -L https://github.com/Mark7766/ai-working-ok/releases/latest/download/ai-working-ok-latest.tar.gz | tar xz -C ~/我的工作项目

第一次使用

  1. 打开 Codex Desktop，进入你的工作文件夹（例如「小红书运营」「Q3 竞品调研」）。
  2. 执行上一步的一句话安装。AI 会接着问你："请一句话告诉我你要做什么？"
  3. 照实回答，例如：我要做一个小红书账号的 Q3 运营规划。
  4. AI 会自动把三层记忆定制成你这个项目，并写好第一条任务记录 —— 然后放心开工。
之后想让它汇报进度，随时说：帮我回顾一下这个项目最近做了什么？ 它会去读记忆文件告诉你。

三层记忆系统

安装后在项目里会生成三个记忆文件（`.github/agent/memory/` 下），分工不同：

  • project-memory.md（长期）：这个项目是什么、目标、关键约定、当前阶段。AI 靠它快速进入状态。
  • decisions-log.md（中期）：你拍板过的决定（工作场景里叫 WDR，Work Decision Record）——为什么这么做。AI 靠它保持前后一致。
  • task-history.md（短期）：每个任务做了什么、结果如何。AI 靠它记得昨天干到哪、下次从哪继续。

规则很简单：开工前读一遍，收尾后更新一遍。这样跨再多对话，AI 都不会失忆。

PDCA 工作流

每个任务都按四步走，保证"有始有终"：

  1. Plan（计划）：读记忆 → 说清这次要做什么、怎么做。
  2. Do（执行）：动手做，产出文档 / 表格 / 方案。
  3. Check（检查）：对照目标和项目标准自查，质量不达标就打回。
  4. Act（沉淀）：把结果、决策、经验写回记忆文件 —— 这一步不可跳过，是"经验不流失"的关键。

整套由项目里的 hooks / 规范自动提醒，不用你盯着。

工作场景

框架自带多种工作场景的工作流和话术模板，覆盖常见的知识工作：

  • 行业调研：竞品、市场、趋势分析
  • 研究报告：长文结构化产出，可追溯到原始资料
  • 方案 / 提案：运营方案、商业计划、投标文件
  • 内容创作：公众号 / 小红书 / 视频脚本
  • 复盘总结：活动复盘、阶段总结
  • 数据分析：口径固定、结论可复现

安装后对 AI 说"给我建一个『调研项目』"之类的需求，它会按对应场景给你搭好结构。

项目结构

安装完成后，你的工作项目里会多出类似这样的骨架：

你的工作项目/
├── AGENTS.md                      # 给 AI 看的"工作台说明书"
├── CLAUDE.md                      # Claude Code 入口（指向 AGENTS.md）
└── .github/agent/
    ├── workflows.md               # 7 类场景工作流
    ├── work-standards.md          # 质量标准
    └── memory/
        ├── project-memory.md      # 项目长期记忆
        ├── decisions-log.md       # 决策记录（WDR）
        └── task-history.md        # 任务流水

推荐把项目相关的产出放在 research/ reports/ plans/ content/ data/ 这类子文件夹里，结构清晰、AI 好找。

常见问题

我不会编程，能装吗？

能。装的过程只需要你"回答一句话"，其余由 AI 完成。它不碰代码。

一定要把工作做成"文件夹项目"吗？

强烈建议。按项目建文件夹（哪怕就是几个 Word/表格），护栏的记忆才有地方存、AI 才有上下文可读。

会不会很重、很啰嗦？

不会。全是 Markdown 和轻量脚本，零依赖；记忆更新由 AI 自动做，你看不到负担。

它和 ai-coding-ok 是什么关系？

是同一套理念的"两兄弟"：ai-coding-ok 面向写代码的开发者，ai-working-ok 面向做工作的知识工作者。两个都装互不冲突，形成"双护栏"。 写代码的项目用 ai-coding-ok，做运营/研究的工作项目用 ai-working-ok。 想了解开发者那一款，可看 ai-coding-ok 文档。
