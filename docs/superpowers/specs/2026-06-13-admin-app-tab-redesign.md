#### "累计页面访问" 精确来源

```javascript
// dashboard.html JS 异步加载
fetch('/api/v1/admin/analytics/page-stats?range_days=365')
  .then(d => d.page_views.forEach(p => total += p.count))
```

对应 SQL：
```sql
SELECT page, COUNT(*) FROM page_events 
WHERE event_type = 'pageview' AND created_at >= datetime('now', '-365 days')
GROUP BY page
```

## 2. 问题诊断

### 问题 1 🔴：累计页面访问放错了 Tab

"累计页面访问 1,054" 是门户网站（codexswtich.cloud）的浏览器 PV，数据来自 `page_events` 表的前端埋点（`portal.js` sendBeacon）。

**它被放在了 App 遥测 Tab 的第四个卡片位置**，跟"事件总数""活跃用户"这两个客户端指标并排。任何人看到这个布局都会认为这是 codex-switch 客户端的 PV，而不是门户网站的 PV。

**结论**：这是一个布局错误。门户 PV 应该属于 Server 运营 Tab（和页面访问柱状图/热门点击放在一起），不应该出现在 App 遥测 Tab 里。

### 问题 2 🔴：功能使用分布被 model_call 主导

```
柱状图效果（8 个 event_type 并排）：
  model_call    ████████████████████████████████████████████ 44
  app_start     ███████ 7
  proxy_start   ███████ 7
  update_check  █████ 5
  其他 4 项     ███ 1-4  ← 完全看不到
```

model_call 是流式高频数据（用户每次发 AI 消息都报），其他 7 种是低频配置操作（启动/安装/写配置，一次性操作）。两类数据性质完全不同，放在一个柱状图里 PK 没有意义。

### 问题 3：事件趋势折线图同样被污染

30 天趋势折线图把所有事件类型混成一条线，model_call 的数量波动完全掩盖了其他事件的变化。

## 3. 优化方案

### 措施 ①：累计页面访问移出 App Tab，改名

| 项目 | 当前 | 改后 |
|------|------|------|
| 位置 | App 遥测 Tab 第 4 卡片 | Server 运营 Tab 卡片行（和页面访问图表放一起） |
| 名称 | 累计页面访问 | 门户 PV（累计） |
| 数据 | 1,054（365 天 pageview） | 不变 |

App Tab 只保留 3 个卡片：事件总数、今日事件、活跃用户(30天)。

### 措施 ②：功能使用分布拆分为两个独立图表

```
改后 App Tab 布局：

┌─ 模型调用活跃度 ────────────────────────────────┐
│  [折线图] 今日 model_call 调用次数，按时间分布    │
│  显示真实调用次数（SUM(count)，非事件条数）       │
│  当前: 约 120 次调用 / 44 条聚合记录             │
└─────────────────────────────────────────────────┘

┌─ 功能使用（配置操作） ──────────────────────────┐
│  [横向柱状图] 排除 model_call，只展示：           │
│  app_start / proxy_start / update_check /       │
│  app_close / proxy_stop / tool_install /        │
│  config_write                                   │
│  各项数值接近，图表有区分度                       │
└─────────────────────────────────────────────────┘
```

### 措施 ③：事件趋势折线图加筛选

加三个按钮切换：
- "全部" — 所有事件合计
- "模型调用" — 只看 model_call（显示 SUM(count) 真实调用量）
- "功能操作" — 排除 model_call，看配置操作趋势

### 措施 ④：model_call 展示真实调用量

当前统计 model_call 用 `COUNT(*)` 统计事件条数（44 条），但客户端聚合后每条记录可能代表多次调用（`properties.count` 可能是 2~8）。真实调用量需要：

```sql
SELECT SUM(
  CASE WHEN json_extract(properties, '$.count') IS NOT NULL 
       THEN CAST(json_extract(properties, '$.count') AS INTEGER) 
       ELSE 1 END
) FROM telemetry_events WHERE event_type = 'model_call'
```
