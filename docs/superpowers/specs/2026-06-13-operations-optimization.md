## 措施 ①：首页 Hero 双按钮 → 单 CTA

### 当前

```
┌──────────────────────────────────────────┐
│  让 AI 编程触手可及                       │
│  Codex Switch 帮你突破网络限制...          │
│                                          │
│  [查看安装指南 →]  [直接下载 →]            │  ← 两个等大按钮
└──────────────────────────────────────────┘
```

### 问题

- 两个按钮分散用户注意力
- "查看安装指南" 点击 78 次，"直接下载" 仅 44 次——但后者仍然占用等同的视觉权重
- 实际用户路径是：Hero → 指南 → 选工具 → 选平台 → 下载。直接跳到下载页的用户需要回来找指南

### 改后

```
┌──────────────────────────────────────────┐
│  让 AI 编程触手可及                       │
│  Codex Switch 帮你突破网络限制...          │
│                                          │
│  [🪟 Windows 安装指南 →]  ← 主按钮        │
│  [🍎 macOS 安装指南 →]    ← 次按钮，小一号  │
└──────────────────────────────────────────┘
```

或者更简单：

```
│  [开始安装 →]                 ← 一个主按钮 │
│  支持 Windows 11 · macOS 11+             │
```

**数据理由**：用户来这里就是为了"怎么装"，不是来浏览的。#1 按钮直通指南，减少一步跳转。

## 措施 ②：下载页 Linux 移除 + 双平台并排直下

### 当前

```
┌────────────────────────────────────────────┐
│  下载 Codex Switch                          │
│  ┌──────────────────────────────────────┐   │
│  │ [macOS] [Windows] [Linux]   ← 三个Tab  │   │
│  ├──────────────────────────────────────┤   │
│  │  当前选中的平台信息 + 下载按钮          │   │
│  └──────────────────────────────────────┘   │
└────────────────────────────────────────────┘
```

### 问题

- Linux 下载量 30 天为 **0**
- Windows + macOS 覆盖 100% 实际用户
- Tab 切换增加一次交互，且默认是 macOS（数据证明大部分用户是 Windows）

### 改后

```
┌──────────────────────────────────────────────────┐
│  下载 Codex Switch                                │
│                                                  │
│  ┌────────────────┐  ┌────────────────┐           │
│  │ 🪟 Windows     │  │ 🍎 macOS       │           │
│  │                │  │                │           │
│  │ v1.8.0         │  │ v1.8.0         │           │
│  │ 74 MB          │  │ 92 MB          │           │
│  │                │  │                │           │
│  │ [下载     ]    │    │ [下载]   │   ← 主按钮  │
│  │                │  │                │           │
│  │ Intel 版本 →   │   │ ARM64 版本 →   │   ← 小字链接│
│  └────────────────┘  └────────────────┘           │
│                                                  │
│  Windows 11 · macOS 11.0+ · Apple Silicon        │
└──────────────────────────────────────────────────┘
```

实际下载分布决定主次：

| 平台 | 主力架构 | 30 天下载 | 次要架构 | 30 天下载 |
|------|---------|----------|---------|----------|
| Windows | **Intel (x64)** | 330 (99%) | ARM64 | 4 (1%) |
| macOS | **ARM64 (Apple Silicon)** | 48 (92%) | Intel (x64) | 4 (8%) |

**效果**：
- 零次 Tab 点击，两个平台直接可见
- 主按钮展示主力架构（Windows x64 / macOS ARM64），覆盖 99% 和 92% 的用户
- 次要架构用小字链接，不抢占视觉空间
- 去掉 Linux（30 天 0 下载，API 保留，前端不展示）
- 保留系统要求说明在底部

**数据理由**：Windows 57% + macOS 14% 覆盖 71% 明确选择，剩余 29% 是未区分平台的下载（来自代码内部调用）。实际的 GUI 用户只选 Win/Mac。

## 措施 ⑤：客户端加首次启动来源上报（长期，需客户端配合）

### 背景

当前只能看到下载量，看不到"下载后有百分之多少的人真正安装成功了"。这是衡量产品健康度的北极星指标。

### 方案

客户端 `app_start` 事件新增可选字段 `install_source`：

| 值 | 含义 |
|---|------|
| `"portal"` | 从 codexswtich.cloud 下载 |
| `"github"` | 从 GitHub Releases 下载 |
| `""` 或不传 | 未知（老客户端） |

服务端在 admin 面板展示 **"安装成功率"**：

```
安装成功率 = 有 app_start 事件的 client_id 数 / 有 download 记录的 IP 数（去重）
```

这个指标比下载量更能反映真实增长。

## 实施优先级

| 优先级 | 措施 | 改动量 | 影响 |
|--------|------|--------|------|
