## 3. UAT 发现并当场修复的缺陷

### D-1【严重·已修复】9 张指南图片在生产返回 403，Windows CLI 流程完全没有插图

**现象**：UAT 走到 Codex CLI · Windows 流程时，发现 9 个步骤里**一张图都没显示**（本地却是好的）。

**定位**（逐层排除）：

```
经 CDN   → 403      ← 不是 CDN 问题
直连源站 → 403      ← 不是 CDN 问题
容器内 ls -l → -rwx------ 1 root root   ← 根因
```

文件在仓库里以 **100755** 提交（本地检出后是 `0700`），Docker 构建原样拷贝 → 容器内是 `root` 所有、`0700`；nginx worker 进程会降权，**读不到 → 403**。

**影响**：`step-cli-*-win.png`、`step-install-codex-windows.png` 等 9 个文件自 **2026-06-06/07** 起就一直不可读——也就是说**指南的 Windows CLI 流程缺图已经 4 个月**。

**修复**（`a7bf446`）：9 个文件改 `0644`（git mode `100755 → 100644`），并在 Dockerfile 加一行兜底 `chmod -R a+rX /app/src/static`，避免同类问题再犯。

**复验**：CDN 与源站 403 全部转 **200**；浏览器逐一渲染成功（751×427、987×760、1891×955 …）。

### D-2【已修复】老访客浏览器仍缓存着失败，图片依旧不显示

D-1 修好后，**同一浏览器**打开指南仍然缺图——因为浏览器把之前的 403 按 URL 缓存了（这些图片没有版本串）。

**修复**（`ea1c7a1`）：给 `img()` 加 `?v=20261007`，改变浏览器缓存键强制重取。这里有个刚查明的细节：**本站 CDN 对 `/static/` 忽略 query string**，所以这个版本串只影响浏览器缓存、不影响 CDN——正好是本次需要的效果。

**复验**：CLI 流程图片从 **2/9 恢复到 9/9**，8 条流程中 6 条**零缺失**。
